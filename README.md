# LangSwitcher

Автоматическое исправление раскладки для macOS — в духе Punto Switcher и Caramba
Switcher. Живёт в строке меню, замечает слова, набранные не в той раскладке,
исправляет их и переключает раскладку за вас.

```
ghbdtn ,скщ    →    привет мир
руддщ цщкдв    →    hello world
```

## Зачем ещё один

Написан для себя, чтобы не зависеть от платных и закрытых переключателей раскладки.
Хотелось трёх вещей: чтобы работало на современной macOS, чтобы исходники были
открыты (программа читает всё, что вы печатаете, — такому коду хочется иметь
возможность заглянуть внутрь), и чтобы ничего никуда не отправлялось.

Ничего не сохраняется на диск и не уходит в сеть. Буфер набранного живёт только
в оперативной памяти, хранит последние 96 нажатий и сбрасывается при щелчке мышью,
смене программы, Enter и Esc. «Дневника» — журнала всего напечатанного, который
есть у некоторых аналогов, — здесь нет намеренно.

## Возможности

- **Автоисправление раскладки.** Слово, набранное не в той раскладке, исправляется
  в момент завершения — пробелом или знаком препинания — вместе с раскладкой.
- **Исправление последнего слова по двойному правому Shift.** Нажмите Shift дважды
  подряд — последнее слово перевернётся. Повторное нажатие вернёт как было.
- **Исправление выделенного текста** — `⌃⌥L`. Если выделения нет, работает как
  двойной Shift.
- **Транслитерация выделенного** — `⌃⌥T` (`привет` ⇄ `privet`).
- **Смена регистра выделенного** — `⌃⌥U` (нижний → ВЕРХНИЙ → Как Заголовок).
- **Автозамена** — свой словарь сокращений, срабатывает на границе слова.
- **Индикатор раскладки** в строке меню, звук при переключении, автозапуск при входе.
- **Исключения** — программы, где ввод не анализируется; по умолчанию туда включены
  терминалы и менеджеры паролей. Горячие клавиши в них продолжают работать.

Все сочетания и клавишу двойного нажатия можно поменять в настройках.

## Установка

Нужен Xcode Command Line Tools и macOS 13+.

```bash
git clone https://github.com/einperegrin/lang-switcher.git
cd lang-switcher
make install
```

Программа соберётся и встанет в `/Applications/LangSwitcher.app`.

### Доступ к вводу

При первом запуске macOS попросит доступ в **Системные настройки →
Конфиденциальность и безопасность → Универсальный доступ**. Без него перехват
клавиатуры невозможен. Программа подхватит разрешение сама, перезапуск не нужен.

### Галочка стоит, а программа всё равно просит доступ

Так бывает после каждой пересборки, и вот почему. У программы нет Developer ID,
поэтому macOS привязывает разрешение к требованию вида
`identifier "com.langswitcher.app" and cdhash H"…"` — то есть **к хешу конкретного
бинарника**. Новая сборка даёт новый хеш, старая запись в базе TCC перестаёт
подходить, но в списке продолжает висеть строка с включённым переключателем.
Снять и поставить галочку не помогает — запись нужно удалить целиком:

```bash
tccutil reset Accessibility com.langswitcher.app
open /Applications/LangSwitcher.app
```

После этого выдайте доступ один раз — запись создастся под актуальный бинарник.
Ту же пару команд печатает `make install`.

Если пересобирать приходится часто, разрешение можно сделать устойчивым: создать
самоподписанный сертификат для подписи кода (Keychain Access → Ассистент
сертификации → Создать сертификат → тип «Подпись кода») и заменить в `Makefile`
`--sign -` на `--sign "Имя сертификата"`. Тогда требование TCC привяжется
к сертификату, а не к хешу, и переживёт пересборки.

## Как это устроено

1. `CGEvent tap` перехватывает нажатия. Для каждого запоминается **физический
   keyCode с модификаторами**, а не только напечатанный символ.
2. Чтобы «перевернуть» слово, те же keyCode заново прогоняются через
   `UCKeyTranslate` с данными другой раскладки. Поэтому в коде нет таблиц вида
   `й→q`, и работает любая пара раскладок, установленных в системе, — хоть русская
   с немецкой.
3. Решение принимает двухступенчатый детектор. Сначала системный словарь
   орфографии (`NSSpellChecker`): слово, которого нет в текущем языке, но которое
   после конвертации становится словарным, — почти наверняка ошибка раскладки.
   Слова вне словарей — а их немало, системный русский словарь не знает даже
   «раскладку» — оценивает фонотактическая модель: допустимые сочетания букв плюс
   доля гласных. Вторая проверка ловит то, что биграммы пропускают: `hfcrkflrf` —
   девять согласных подряд, для настоящего слова невозможная картина.
4. Исправление выполняется backspace'ами и вставкой через unicode-события, поэтому
   не зависит от активной раскладки.

Порог срабатывания намеренно консервативный: пропустить исправление менее неприятно,
чем испортить правильно набранное слово.

## Разработка

```bash
swift build -c release
.build/release/LangSwitcher --selftest   # 43 проверки на ваших раскладках
make run                                 # собрать и запустить, не устанавливая
```

Самотест синтезирует настоящие keyCode из установленных раскладок и прогоняет весь
путь целиком — от физической клавиши до решения детектора, включая проверки на
ложные срабатывания (`npm`, `git`, `ssh`, `kubectl` трогать нельзя).

## Ограничения

- **Предложения из слов разных языков** обрабатываются пословно, и это работает
  хуже, чем однородный текст: короткие иноязычные вкрапления детектор часто
  пропускает. Двойной Shift на такой случай и нужен.
- Двойной Shift правит слово из внутреннего буфера. Если вы кликнули мышью
  в другое место или переключили программу, буфер пуст — программа коротко пикнет.
- В полях ввода пароля macOS не отдаёт события никаким программам, включая эту.
  Это правильно и не лечится.
- Работа с выделенным текстом использует буфер обмена (⌘C/⌘V) и затем возвращает
  его прежнее содержимое.
